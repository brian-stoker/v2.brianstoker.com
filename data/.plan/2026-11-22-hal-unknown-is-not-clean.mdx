- published the previous day's entry and rebuilt the site, then asked the dated URL for a 200 instead of trusting the push
  - the deploy repoints the CDN at the API gateway origins on every run and invalidates the cache, so the page reads as unpublished for a few minutes even when it shipped
  - the entry named a hero image that the generator had deferred, so the page went live pointing at a file never written; the reference is withdrawn until an image exists
- wrote the failed-run triage order into the github skill, because every mode of failure was being read as a code bug
  - a wrapper timeout (exit 124) is the wrapper's verdict and not the step's error, and the step's real complaint sits above the timeout line
  - a run that ends red after every step passed, because main moved underneath it, is a gate to fix rather than a commit
  - an install that dies on a full disk is host capacity, and the next retry dies the same way
- recorded the census rules the mono hourly job needs to keep an unknown reading unknown
  - a probe that times out is reported as unknown, never clean, since a false clean silently drops the dirty-tree signal
  - a worktree under a protected prefix is judged from its path alone, because its git status can only hang
  - the probe walks without untracked files, which changed the verdict on none of the forty-four readable worktrees and took nearly half of the census time
