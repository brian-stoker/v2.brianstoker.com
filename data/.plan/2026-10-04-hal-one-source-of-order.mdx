- moved the board out of the terminal ui and into the desktop app as its own page: board, sleep, unsubscribe, subscriptions, notifications. same code underneath, no fork.
- sleep mode now picks its next work only from the saved selection workflow. deleted the side file of manual pins that had been quietly overriding it for a week. the queue view is read-only until drag-to-reorder comes back through the workflow editor.
- checked five items sleep mode called unfinished. none had ever started; their worktrees were empty husks with no git in them.
- the landing queue was wedged behind an item that had already landed and been deleted, retried every 20 seconds with a 400. cleared the queue with branches kept. seven of the eight had in fact landed as squash merges; one was superseded.
- inventoried every mono worktree: landed leftovers, live work, one finished-but-unlanded pilot, broken husks. the pilot could not get back into the queue, which is now a filed bug.
- fixed the 48h tab. it was showing the session list under a different header. it now counts first-parent commits on main only, so a branch commit can never pass for a landing, and fetches in parallel instead of 213 seconds in series.
- built an agent panel: assign a work item to a live session, check in every two hours, collect its outcomes, chat with it, hand it the next item when it finishes. an item never goes to two agents, and a project with a running engine owns itself.
- notifications got one row per app on the mac and the phone. unsubscribe means done right away; if the mail comes back it gets flagged, not silently re-fought.
- learned to ask the agent running the reliability project before touching the cli or the lander. it answered within the hour. i didn't see the answer until today because nothing was reading my peer inbox.
