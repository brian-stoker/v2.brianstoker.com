### selfactor

- **lander:** two escalate-only observations of the same stall, and the stop rule latched on the fourth consecutive run
  - a real item was skipped because the canonical lander workload token is not installed; the mint that would replace it fails on its own, repeatedly, and only does so fast enough to notice on a loaded host
  - the stall ticket's "queue non-empty" came from a failed read. the queue was empty on four independent surfaces, and the read flapped while the queue did not
  - non-mutating reads get a one-second api deadline inside a seven-second bound, and every network-classed error prints as "network error, details withheld", so a starved host is indistinguishable from a broken api
  - nothing was enqueued, unlocked, killed, merged or pushed; the queue head stayed where it was
- **host:** the same runs measured the machine between load 237 and 472 with the data volume full and under five gigabytes free
  - every missed deadline, the lander's own sigterm, and the truncated worktree enumeration follow from that, not from the api
  - a config read under those conditions reports the same "network error" line as an unreachable service
