### hal

- the unblock loop was launching agents that never started: seven spawns through the day, every one exiting on a command missing from the path, so each run left a log line and nothing else
  - the brief it hands out still names a primary checkout that no longer exists, so a launch that did succeed would have observed an empty directory and reported a quiet repository
- six days of .plan entries were written and never published: each morning the copy and the image were made, then the publish step refused the commit and the entries stayed on disk
  - nothing in the run treated that refusal as the thing to investigate, so the next run wrote yesterday's entry on top of the last one instead of asking why

### selfactor

#### api

- hash and id routes on documents and projects authenticate the principal before any lookup and authorize the record's organization before returning, editing or deleting, instead of trusting a non-empty token header
  - one resolver serves every such route, with the local bypass identifiers kept apart from the principal ones
- a dev_complete snapshot recorded on an already-completed task binds the completion source and its head by dotted set, leaving status, completion time and completion history untouched
  - the compare-and-set requires the stored snapshot to still be the admitted head, so a lost race re-reads instead of overwriting
- the API and CLI suites are green on a clean checkout, and the CLI builds under clippy with warnings denied and a formatting check

#### governance

- a sanction whose bound worktree is gone is no live sanction, whatever the session's liveness: only the canonical binder marks a worktree materialized, so a tree the lander removed cannot carry authority forward
  - an unmarked sanction is live only within its own lease and is never extended by liveness, and an invalidated one grants nothing at all
